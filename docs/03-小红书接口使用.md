> 面向：要抓数 / 要看签名头 / 要判断额度与封禁
> 依据：9.51.0 APK 全部 22 个 dex 静态提取 + 线上实测；最后核对 2026-10-26 04:00

## 一、请求必须带的签名头

**权威清单（dex 拦截器里的 11 个，先 `removeHeader` 再重设 —— 反伪造设计，手动塞同名头会被删）**：

```
shield
xy-common-params
xy-platform-info
x-mini-mua
x-mini-sig
x-mini-gid
x-legacy-sid
x-legacy-fid
x-legacy-did
x-xray-traceid
X-B3-TraceId
```

> `xy-scene` / `xy-direction` 走**参数**不走这个拦截器，但参与 shield source。

**本项目实际发送 17 个头**，其中签名头只有 3 个：

| 头 | 内容 | 长度 |
|---|---|---|
| `x-mini-sig` | **s1**（62 字节）：`00 | counter | 01 | CBC(seed44) 48B | CRC4 | CRC4` | 经 base64 后见实际值 |
| `x-mini-mua` | mua（85 字段的 `d` 段 + `s` 段，v2.10.1） | 长串 |
| `x-mini-gid` | gid（本地随机 28 字节，不参与签名、服务端不校验） | — |
| `shield` | `"XY" + base64(RC4(KEY, plain))` | 98 字符 |

**`x-mini-s1` 这个头不存在**——dex 全量 22 个里零命中。62 字节那个东西的真名是 `x-mini-sig`，以前多发一个 `x-mini-s1` 属于脏指纹，已于 2026-10-26 移除。

### s1 的结构

```
00 | counter(4B LE) | 01 | AES-128-CBC(seed44 → 48B) | CRC4 | CRC4       共 62B

seed44 = ts(4B) | enc_seq(perm8, 4B) | 0000 | lane32(4B) | enc_seq(perm4, 2B)

enc_seq: 每字节 = 10*A + B (A,B ∈ 1..8, A≠B)，4 字节 → 8 个数字 = 1..8 的排列
perm8 生成：seed = ts → bionic random()（31 状态，预热 310 次）→ 7 个 rand
            → 对常量 Q=[2,4,1,6,7,3,8,5] 做倒序 Fisher-Yates
```

`perm8` 已完全破解并接入生产（`xhs_perm.py`，320/320 真实样本逐字节一致）。
`perm4` 那 2 字节**仍未破解**，当前用恒等 `[0,1,2,3]`；服务端不校验 s1，不影响可用性。

## 二、吃额度的接口只有 7 个

实测 `GET /api/reverse/quota`：

```
/api/sns/v6/homefeed          feed      首页主 feed
/api/sns/v1/note/basic/homefeed  feed   首页基础 feed
/api/sns/v1/note/imagefeed    feed      图文 feed
/api/sns/v3/note/videofeed    feed      视频 feed（v3）
/api/sns/v4/note/videofeed    feed      视频 feed（v4）
/api/sns/v1/note/detailfeed/preload  detail   详情预载
/api/sns/v10/search/notes     search    搜索笔记
```

**额度实测结论**：

- 详情族是**内容额度**，远小于普通接口：连打 20 次 `imagefeed`，**第 13 次起降级**，随后 `461 + code=0`，**>25 分钟未恢复**（疑滚动窗口）
- 打穿后连 `posted` 也归零 ⇒ **一见 `461 / code=0` 立刻停手**
- 「1 秒一次连打 60 次全过」只适用于**普通接口**（`posted` / `user/info` / 配置类）
- 造设备：≥1.5 秒/台（0.7 秒/台时第 6 台起 `-100`）

**判断某个接口吃不吃额度**：

```bash
curl -s "http://YOUR_HOST/api/reverse/classify?path=/api/sns/v1/note/collection/list" \
     -H "Authorization: Bearer $TOK"
# → {"family":"内容详情","quota_kind":"normal","is_quota":false,"known":true}
```

⚠️ **不要按名字猜**：286 个带 `note` 的接口里，绝大多数是 `note/collection/*`、`note/widget/*`、
`search/*/guide` 这类**配置/引导接口**，不吃额度。

## 三、封禁三码

| 现象 | 含义 | 处理 |
|---|---|---|
| `-100 请登录账号` | 会话级（游客准入 / session 失效） | 游客准入不退避；登录态失效要重登 |
| `-100` 其它文案 | 会话 / IP 层 | 换设备或等窗口 |
| `300011` | **账号层异常** | 换设备；换 IP 无效，持续 >48h |
| `461` + `code=0` | **纯限流** | 停 6 分钟以上自愈 |
| `461` + `300011` | 账号异常 | 同 300011 |
| `406` 空 body | 无会话 | 设备未登录 |
| 登录限流 `crawl_interval_ms` | **必须 ≥1000**（300 是自杀配置） | 密度比总量致命 |

判成功标准：**`http == 200 且 code == 0`**。`-100 / 461 / 300011` 全是 HTTP 200，只看状态码会误判。

## 四、本项目的抓取方式

```
每轮：取一台 active 设备 → GET /api/sns/v4/note/user/posted?num=N → 合并去重 → 推送
```

- 单账号单设备，不并发轰炸
- `crawl_interval_ms` 默认 1000，相邻博主之间强制间隔
- 设备失效（`-100`）→ 标 `expired`，不再用
- 游客态、代理池、自动建号**都不在这版**（已移除）

## 六、签名代码在哪

| 用途 | 位置 |
|---|---|
| 9.49.1 签名（当前主轨） | `xhs_core_9491.py` → `XhsSigner9491` |
| 9.19.2 签名（存量兼容） | `xhs_core.py` → `XhsSigner` |

| 设备材料生成 | `device_factory.generate_offline()` |
| s1 的 perm8 | `xhs_perm.make_perm8_zero(ts)` |
